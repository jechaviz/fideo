# Fideo Design Principles

These are decision tools for Fideo UI work. Use them when a design has multiple defensible options.

1. Prefer what matters now.
   If a screen is crowded, keep the operational state, next risk, and next action visible before brand expression or decorative hierarchy.

2. Make action obvious, keep context adjacent.
   Primary actions should sit next to the metrics or status they affect. Do not isolate a button from the reason to use it.

3. Design for pressure, not browsing.
   Staff may be packing, routing, selling, or resolving an exception. Favor dense, scannable information with strong focus states and predictable controls.

4. Ship self-contained surfaces.
   Production UI should not depend on runtime design CDNs. Fonts, icons, Tailwind utilities, and app styles must be built, versioned, and auditable with the app.
